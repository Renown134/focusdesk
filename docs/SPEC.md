# SPEC: FocusDesk

Техническая спецификация. Отвечает на вопрос «как устроено», продуктовые требования —
в [PRD.md](PRD.md), мотивы решений — в [DECISIONS.md](DECISIONS.md).

- **Версия:** 1.0
- **Дата:** 5 ноября 2026
- **Статус:** соответствует версии 1.0 в `main`; актуальный код —
  в истории репозитория.

## 1. Область

Одностраничное клиентское приложение без бэкенда. Входных данных извне нет, сетевых
запросов нет, состояния между сессиями нет. Всё, что описано ниже, исполняется в браузере,
кроме локального статического сервера для разработки.

## 2. Архитектура

```
┌──────────────────────────── index.html ────────────────────────────┐
│  статический каркас: header, intro, #focus-form > #tasks, #result  │
└───────────────┬───────────────────────────────────┬────────────────┘
                │ <script type="module">           │ <link rel="stylesheet">
                ▼                                   ▼
        assets/app.js  ──импорт──►  assets/scoring.js    assets/styles.css
        (DOM, события,              (чистые функции:      (токены, сетка,
         рендер, фокус)              оценки, выбор,        адаптив, анимации)
                                     объяснения,
                                     валидация)
                │
                ▼
        tests/scoring.test.mjs  (node:test, без DOM)
```

Принципы:

1. **Модель отделена от представления.** `scoring.js` не знает про DOM и браузер, поэтому
   тестируется в Node и может быть перенесён в другой рантайм.
2. **Однонаправленный поток.** Пользователь → событие формы → чтение состояния из DOM →
   чистые функции → рендер результата.
3. **Нет сборки.** Браузер загружает те же файлы, что лежат в репозитории. GitHub Pages
   отдаёт их без пайплайна.

## 4. Модель данных

```js
// assets/scoring.js
export const SCALE_MIN = 1;
export const SCALE_MAX = 5;
export const TASKS_REQUIRED = 3;

/** @typedef {{ name: string, impact: number, urgency: number }} Task */
/** @typedef {Task & { index: number, score: number }} RankedTask */
```

`index` — позиция задачи в порядке ввода (0..2), она же `data-index` в DOM. Оценки — целые
числа 1..5; `NaN` означает «не выбрано» и не проходит валидацию.

Результат выбора:

```js
{
  ranked: RankedTask[],        // все три задачи по убыванию приоритета
  winner: RankedTask,          // карточка фокуса
  runnerUp: RankedTask | null, // вторая задача (всегда есть при трёх задачах)
  gap: number | null,          // winner.score - runnerUp.score, 0 при равенстве
  tieBreak: 'urgency' | 'order' | null
}
```

Состояние приложения отдельно не хранится: источник истины — DOM формы (значения input и
отмеченные radio). Это осознанно: данных мало, синхронизация двух копий состояния не нужна.

## 5. Алгоритмы

### 5.1 Оценка

```js
scoreOf(task) = task.impact + task.urgency   // 2..10
```

### 5.2 Ранжирование

Компаратор строго лексикографический:

```js
if (b.score !== a.score) return b.score - a.score;   // больше баллов — выше
if (b.urgency !== a.urgency) return b.urgency - a.urgency; // больше срочности — выше
return a.index - b.index;                            // раньше введена — выше
```

`rankTasks` копирует задачи (`{ ...task, index, score }`) и сортирует копию: исходный
массив не мутируется, индексы сохраняются.

### 5.3 Выбор фокуса

```js
chooseFocus(tasks) {
  if (tasks.length !== 3) throw new RangeError(...);
  const ranked = rankTasks(tasks);
  const [winner, runnerUp] = ranked;
  const gap = winner.score - runnerUp.score;
  const tieBreak = gap > 0 ? null
    : winner.urgency > runnerUp.urgency ? 'urgency'
    : 'order';
  return { ranked, winner, runnerUp, gap, tieBreak };
}
```

### 5.4 Объяснение

`explainChoice(choice)` возвращает массив строк (2–3 элемента):

1. Всегда: `Итоговая оценка — {score} из 10: влияние {impact}/5, срочность {urgency}/5.`
2. Если `gap > 0`: `Ближайшая альтернатива — «{runnerUp.name}»: {N баллов}; отрыв {gap} {балл|балла|баллов}.`
3. Если `tieBreak === 'urgency'`: `У «{runnerUp.name}» столько же баллов, но срочность ниже:
   {runnerUp.urgency} против {winner.urgency}. При равенстве баллов решает срочность.`
4. Если `tieBreak === 'order'`: `У «{runnerUp.name}» совпали и балл, и срочность — выбрана
   задача, которую вы ввели раньше.`
5. Профиль задачи по порогам:

| Условие | Текст |
| --- | --- |
| `impact >= 4 && urgency >= 4` | Высокое влияние и высокая срочность: задача двигает результат и не терпит отсрочки. |
| `impact >= 4 && urgency <= 2` | Влияние заметно выше срочности: это важная работа, которая легко теряется в текучке. |
| `urgency >= 4 && impact <= 2` | Срочность выше влияния: задачу нужно закрыть сегодня, но на результат недели она повлияет слабо. |
| `impact <= 2 && urgency <= 2` | Обе оценки низкие: фокус достаётся этой задаче только потому, что остальные ещё легче отложить. |
| иначе | Сбалансированная ставка: влияние и срочность близки, без крайностей. |

Склонение чисел — функция `plural(n, one, few, many)` по правилам русского языка
(11–14 → «баллов», 1 → «балл», 2–4 → «балла»).

Объяснение детерминировано: одинаковые входные данные всегда дают одинаковый текст. Это
позволяет проверять его регулярками в тестах.

## 6. Валидация

`validateTasks(tasks)` возвращает `{ ok, errors: [{ index, field, message }] }`, где
`field ∈ {'tasks', 'name', 'impact', 'urgency'}`, `index` — номер задачи или `null`.

| Проверка | Сообщение |
| --- | --- |
| Не массив из трёх элементов | `Нужно ровно 3 задачи.` (`field: 'tasks'`) |
| Имя пустое после `trim()` | `Введите название задачи.` |
| Имя длиннее 120 символов | `Название длиннее 120 символов.` |
| Оценка не целое 1..5 | `Выберите оценку от 1 до 5.` |

Интерфейс показывает первое сообщение с префиксом `Задача N:` в `#form-error`
(`role="alert"`), ставит `aria-invalid` и класс `is-invalid` на соответствующий контрол,
показывает локальную подсказку `.scale__error` и переводит фокус на первое невалидное поле.

## 7. DOM-контракт

Эти селекторы — публичный контракт между разметкой, скриптом и стилями. Менять их можно
только вместе с CSS, тестами и этим разделом.

### Каркас (`index.html`)

| Селектор | Назначение |
| --- | --- |
| `#focus-form` | Форма; `novalidate`, отправка перехватывается. |
| `#tasks` | Контейнер, который `app.js` заполняет тремя карточками. |
| `#form-error` | Сводка ошибок, `role="alert"`, скрыта по умолчанию. |
| `#result` | Секция результата, `tabindex="-1"`, `aria-labelledby="focus-title"`, скрыта. |
| `#focus-title` | Заголовок карточки, на него ссылается `aria-labelledby`. |

### Карточка задачи (генерируется)

```html
<article class="task" data-index="{i}">
  <input id="name-{i}" name="name-{i}" class="task__input" maxlength="120">
  <output class="task__score" data-score="{i}" aria-hidden="true">—</output>

  <fieldset class="scale" data-kind="impact">
    <input type="radio" name="impact-{i}" value="{1..5}" id="impact-{i}-{v}">
    <p class="scale__error" data-error="impact-{i}" hidden></p>
  </fieldset>
  <fieldset class="scale" data-kind="urgency"> … name="urgency-{i}" … </fieldset>
</article>
```

Имена радиогрупп: `impact-{i}` и `urgency-{i}`, значения — строки `'1'..'5'`, чтение через
`Number(value)`. Отсутствие отмеченного radio → `NaN`.

### Результат (генерируется)

| Селектор | Содержимое |
| --- | --- |
| `.focus-card` | Тёмная карточка фокуса. |
| `.focus-card__title` | Название победившей задачи (экранировано). |
| `.score__value` / `.score__total` | Балл и «из 10». |
| `.metric` × 2 | Влияние и срочность, ширина заливки `value / 5 * 100%`. |
| `.focus-card__tie` | Пометка тай-брейка, если он сработал. |
| `.reasons li` | Строки объяснения. |
| `.rank-row` | Строка рейтинга; `.is-winner` у победителя. |
| `.rank-row__place/__name/__score` | Место, название, балл. |
| `[data-action="edit"]` / `[data-action="reset"]` | Действия после результата. |

### События

| Событие | Обработка |
| --- | --- |
| `input` внутри `.task` | `updateScores()`; если ошибка видима — `clearErrors()`. |
| `change` на radio | Снять локальную ошибку шкалы, `updateScores()`, `syncSegmentStates()`. |
| `submit` формы | `readTasks()` → `validateTasks()` → ошибки или `chooseFocus()` + `renderResult()`. |
| `click` в `#result` | Делегирование по `[data-action]`: `edit` / `reset`. |

`renderResult` снимает `hidden`, добавляет `is-visible` в `requestAnimationFrame`, переводит
фокус на `#result` (не на заголовок — так скринридер объявляет секцию целиком) и прокручивает
её в видимую область.

## 8. Состояния интерфейса

```
idle ──ввод──► editing ──submit(невалидно)──► error ──исправление──► editing
                  │
                  └──submit(валидно)──► result ──edit──► editing
                                          └──reset──► idle
```

| Состояние | Признаки |
| --- | --- |
| `idle` | Пустые поля, чипы «—», результат скрыт. |
| `editing` | Есть значения, чипы показывают сумму, ошибок нет. |
| `error` | `#form-error` видим, `aria-invalid` на полях, фокус на первом невалидном. |
| `result` | `#result` видим, фокус на секции, форма остаётся выше с сохранёнными значениями. |

## 9. Оформление

- Токены в `:root`: бумажный фон `--paper`, поверхности `--surface`, чернила `--ink`,
  акцент `--accent` (терракота), тёмная карточка `--focus-bg`.
- Типографика: системный гротеск для интерфейса, антиква (`Iowan Old Style`/`Palatino`/
  `Georgia`) для заголовков, моноширинный для чисел и меток. Веб-шрифты не загружаются.
- Сетка: `.shell` шириной `min(1080px, 100% - 48px)`; карточки задач — вертикальный список;
  шкалы — две колонки.
- Брейкпоинты: `820px` (одна колонка шкал, метрики в столбик) и `560px` (компактная
  карточка, полноширинные кнопки, скрытый декоративный номер).
- Анимация появления результата отключается через `prefers-reduced-motion: reduce`.
- Выбранный сегмент стилизуется `input:checked + .segment__face`; класс `is-checked`
  дублирует состояние для сред без `:has()`.

## 10. Локальный сервер

`server.mjs`:

- порт `PORT` или `5173`, привязка к `127.0.0.1`;
- только `GET` и `HEAD`, иначе `405` с заголовком `Allow`;
- MIME по расширению (`.html`, `.css`, `.js`, `.mjs`, `.svg`, `.png`, `.ico`, `.json`, `.woff2`);
- `/` отдаёт `index.html`, каталог — свой `index.html`;
- защита от обхода путей: `decodeURIComponent` → `normalize(join(root, relative))` →
  проверка префикса; ошибка декодирования или выход за корень → `403`;
- отсутствующий файл → `404`;
- `Cache-Control: no-cache`.

Сервер не является частью продакшена: на GitHub Pages используется встроенный статический
хостинг.

## 11. Качество

### Доступность

- нативные `fieldset`/`legend` и radio, а не кнопки с `aria-pressed`;
- видимый `:focus-visible` у всех интерактивных элементов;
- `#form-error` с `role="alert"`;
- фокус переводится на первое невалидное поле и на секцию результата;
- декоративные элементы скрыты `aria-hidden`;
- контраст текста на бумаге и на тёмной карточке выше 4.5:1 для основного текста;
- поддержка `prefers-reduced-motion`.

### Производительность

- ноль внешних запросов, шрифтов и изображений в интерфейсе;
- один HTML, один CSS, два JS-модуля; суммарно менее 40 КБ без сжатия;
- вся разметка задач генерируется один раз при загрузке.

### Приватность и безопасность

- нет сети, cookies, `localStorage`, `sessionStorage`, URL-состояния;
- пользовательские строки экранируются `escapeHtml` перед вставкой в `innerHTML`;
- сервер не отдаёт файлы за пределами корня репозитория.

### Совместимость

Современные evergreen-браузеры (Chrome/Edge 105+, Firefox 121+, Safari 15.4+). Требуются
ES-модули, `String.prototype.replaceAll`, optional chaining, CSS `clamp()` и grid.
Транспиляции и полифилов нет.

## 12. Тестирование

`tests/scoring.test.mjs` покрывает:

1. сумму оценок;
2. выбор по максимальному баллу и корректный `gap`;
3. тай-брейк по срочности;
4. тай-брейк по порядку ввода;
5. отсутствие мутации входного массива;
6. `RangeError` при числе задач, отличном от трёх;
7. текст объяснения при тай-брейке;
8. текст объяснения с отрывом;
9. валидную тройку;
10. пустое имя, нечисловые/выходящие за шкалу оценки, неверное число задач.

Запуск: `npm test` (обнаружение через `node --test`) или
`node --test tests/scoring.test.mjs`. CI — `.github/workflows/tests.yml`, Node 20.

Ручная проверка интерфейса описана в [AGENTS.md](../AGENTS.md) (чек-лист).

## 14. Точки расширения

| Что | Где менять | Ограничение |
| --- | --- | --- |
| Новое правило приоритизации | `scoring.js` + тесты + PRD | Меняет продукт, нужен новый PRD. |
| Веса влияния/срочности | `scoreOf` + тексты + UI | Объяснение должно оставаться проверяемым. |
| Локализация | тексты `app.js`/`scoring.js` | Потребует словаря и переключения языка. |
| Копирование карточки | `app.js` (Clipboard API) | Не должно добавлять хранение. |
| Печать | `styles.css` (`@media print`) | Без внешних ресурсов. |
| Автотесты браузера | отдельный каталог | Не должны попадать в runtime-бандл. |
