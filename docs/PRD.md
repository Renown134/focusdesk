# PRD: FocusDesk

- **Статус:** реализовано, версия 1.0
- **Дата:** 5 ноября 2026
- **Автор:** учебный кейс продуктового выбора
- **Демо:** https://renown134.github.io/focusdesk/

## 1. Контекст

У продакт-менеджера почти всегда больше трёх задач, которые выглядят важными. Утро уходит
на переключение между ними, а к вечеру ни одна не продвинулась достаточно. Проблема не в
нехватке списка дел, а в отсутствии одного решения: **с чего начать сегодня**.

FocusDesk не ведёт задачи и не планирует день. Он заставляет явно сравнить три кандидата
по двум осям и выдаёт одну карточку фокуса с объяснением — чтобы решение можно было
принять за минуту и не пересматривать его до обеда.

## 2. Проблема

- Слишком много параллельных «важных» задач, выбор откладывается.
- Приоритеты хранятся в голове и меняются от настроения.
- Интуитивный выбор не объясним: через час непонятно, почему начали именно с этого.

## 3. Пользователь

Продакт-менеджер, который начинает рабочий день и готов потратить на выбор до минуты.
Ему не нужен ещё один трекер — нужен короткий ритуал принятия решения.

**Job to be done:** «Когда я открываю рабочий день с тремя конкурирующими задачами, я хочу
выбрать одну и понять почему, чтобы не распыляться и не сомневаться в выборе».

## 4. Цель и метрики

| Цель | Метрика | Целевое значение |
| --- | --- | --- |
| Быстрый выбор | Время от открытия до карточки фокуса | до 60 секунд |
| Понятность | Доля пользователей, которые могут пересказать причину выбора | 100% в тестах |
| Корректность | Доля равных баллов, решённых по срочности | 100% |
| Простота | Количество экранов до результата | 1 |

Для учебного кейса метрики проверяются качественно и тестами логики, без аналитики.

## 5. Сценарий

1. Пользователь открывает FocusDesk.
2. Вводит три задачи.
3. Для каждой выбирает влияние (1–5) и срочность (1–5).
4. Нажимает «Выбрать фокус».
5. Получает карточку: название задачи, балл, шкалы, объяснение и рейтинг всех трёх задач.
6. Может вернуться к редактированию или начать заново.

## 6. Границы

**Входит в кейс:**

- ровно три задачи, введённые вручную;
- две оценки на задачу: влияние и срочность;
- один результат — карточка фокуса;
- объяснение выбора и распределение мест;
- работа без сети и без сохранения данных.

**Не входит:**

- календарь и планирование слотов;
- трекер задач, статусы, дедлайны;
- авторизация и синхронизация;
- реальные рабочие данные и интеграции;
- генерация кода или текстов нейросетью;
- истории, статистика, настройки.

## 7. Функциональные требования

| ID | Требование | Приоритет |
| --- | --- | --- |
| FR-1 | Форма содержит ровно три задачи. | must |
| FR-2 | У каждой задачи есть текстовое название (до 120 символов). | must |
| FR-3 | У каждой задачи есть оценка влияния от 1 до 5. | must |
| FR-4 | У каждой задачи есть оценка срочности от 1 до 5. | must |
| FR-5 | Итоговая оценка = влияние + срочность. | must |
| FR-6 | Победитель определяется по итоговой оценке. | must |
| FR-7 | При равенстве оценок побеждает большая срочность. | must |
| FR-8 | При равенстве оценок и срочности побеждает задача, введённая раньше. | must |
| FR-9 | Результат показывает одну карточку фокуса с баллом и объяснением. | must |
| FR-10 | Объяснение называет балл, отрыв или сработавший тай-брейк и профиль задачи. | must |
| FR-11 | Результат показывает распределение всех трёх задач по местам. | should |
| FR-12 | Незаполненные поля подсвечиваются, отправка блокируется. | must |
| FR-13 | Кнопка «Изменить задачи» возвращает к форме с сохранёнными значениями. | should |
| FR-14 | Кнопка «Начать заново» очищает форму и результат. | should |
| FR-15 | Данные не сохраняются между перезагрузками страницы. | must |

## 8. Правила приоритизации

```
score(task) = impact + urgency          # 2..10

rank(tasks) = sort by:
  score desc,
  urgency desc,
  index asc                            # порядок ввода

focus = rank(tasks)[0]
```

Тай-брейк по срочности выбран потому, что при равной сумме задача, которую нельзя
отложить, приносит больше пользы сегодня. Порядок ввода — последний детерминированный
критерий: он гарантирует, что результат не зависит от случайности.

## 9. Состояния интерфейса

| Состояние | Что видит пользователь |
| --- | --- |
| Пустая форма | Три карточки, плейсхолдеры, неактивные шкалы. |
| Заполнение | Выбранные сегменты и живой балл задачи; кнопка доступна. |
| Ошибка | Поле подсвечено, сообщение с номером задачи, фокус на первом незаполненном поле. |
| Результат | Карточка фокуса, объяснение, рейтинг, действия. |
| Сброс | Пустая форма, фокус в первой задаче. |

## 10. Нефункциональные требования

- **Доступность:** семантические `fieldset`/`legend`, радиогруппы, видимый фокус, `aria-live`
  для ошибки, поддержка `prefers-reduced-motion`.
- **Адаптивность:** один столбец на мобильных, две шкалы в ряд на широких экранах.
- **Производительность:** без внешних зависимостей и веб-шрифтов; несколько статических файлов.
- **Приватность:** никаких сетевых запросов и хранения.
- **Поддерживаемость:** логика отделена от DOM и покрыта тестами.

## 11. Критерии приёмки

1. **Выбор по баллам.** Дано: 5/4, 3/5, 2/2. Тогда карточка — первая задача с 9 баллами.
2. **Равенство баллов.** Дано: 5/2 и 2/5. Тогда побеждает вторая задача, в объяснении
   сказано, что решила срочность.
3. **Полное равенство.** Дано: 4/3 и 4/3. Тогда побеждает введённая раньше, в объяснении
   упомянут порядок ввода.
4. **Незаполненная форма.** Тогда отправка блокируется, первое пустое поле получает фокус,
   рядом с задачей — сообщение об ошибке.
5. **Три задачи.** Добавить четвёртую или удалить задачу нельзя.
6. **Приватность.** После перезагрузки страницы данных нет.

## 12. Что дальше (вне кейса)

- Перенос объяснения на естественный язык с учётом контекста недели.
- Сравнение с прошлым выбором без хранения персональных данных.
- Настройка весов влияния и срочности под роль.
- Экспорт карточки в заметки или мессенджер.

Любой из пунктов требует отдельного решения о хранении данных и выходит за границы
текущего кейса.
