# AGENTS.md

Практическое руководство для ИИ-агентов и контрибьюторов, которые меняют код FocusDesk.
Человеческое введение — в [README.md](README.md), продуктовые требования — в
[docs/PRD.md](docs/PRD.md), техническая спецификация — в [docs/SPEC.md](docs/SPEC.md).

## Что это за проект

FocusDesk — статическое веб-приложение без сервера и зависимостей. Пользователь вводит
три задачи, оценивает влияние и срочность по шкале 1–5, получает одну карточку фокуса с
объяснением. Вся логика выбора — чистые функции в `assets/scoring.js`, интерфейс — в
`assets/app.js`.

Ключевое ограничение: **это не трекер задач**. Никакого хранения, календаря, авторизации,
сети и генерации текста нейросетью.

## Быстрый старт

```bash
node server.mjs          # http://127.0.0.1:5173
npm test                 # 10 unit-тестов на node:test
```

`npm install` не нужен: зависимостей нет. ES-модули не работают из `file://`, поэтому
открывать `index.html` двойным кликом бессмысленно — нужен HTTP-сервер.

## Карта репозитория

| Путь | Ответственность | Когда трогать |
| --- | --- | --- |
| `index.html` | Каркас страницы, мета-теги, контейнеры `#tasks` и `#result`. | Метаданные, статическая разметка, тексты вне карточек. |
| `assets/scoring.js` | Модель: оценки, ранжирование, тай-брейки, объяснения, валидация. Без DOM. | Любое изменение правил выбора. |
| `assets/app.js` | Состояние формы, генерация разметки задач, ошибки, рендер результата, фокус. | Взаимодействие и представление. |
| `assets/styles.css` | Токены оформления, сетка, адаптив, анимации. | Визуальные изменения. |
| `server.mjs` | Локальный статический сервер (`node:http`), MIME, защита от обхода путей. | Инфраструктура локального запуска. |
| `tests/scoring.test.mjs` | Контракт правил: сумма, порядок, тай-брейки, тексты, валидация. | Вместе с любым изменением `scoring.js`. |
| `docs/PRD.md` | Зачем продукт, требования, критерии приёмки. | Изменение поведения или границ. |
| `docs/SPEC.md` | Как устроено: модель, алгоритмы, DOM-контракт, сервер, качество. | Изменение архитектуры или контрактов. |
| `docs/DECISIONS.md` | Почему приняты ключевые решения. | Новое архитектурное решение. |
| `PLAN.md` | Что сделано и что дальше. | Закрытие или добавление задачи. |

## Инварианты

Нарушение любого пункта — это не «мелкая правка», а изменение продукта. Сначала обновите
PRD, тесты и объяснение в интерфейсе.

1. Ровно три задачи. Четвёртой строки, удаления и переупорядочивания нет.
2. Влияние и срочность — целые числа от 1 до 5. Итог — сумма, от 2 до 10.
3. При равной сумме побеждает большая срочность; при равенстве и суммы, и срочности —
   задача, введённая раньше. Порядок ввода — детерминированный последний критерий.
4. Результат всегда один: карточка фокуса. Никаких «топ-3» вместо решения.
5. Данные не сохраняются: ни `localStorage`, ни cookies, ни сети, ни URL-состояния.
6. Интерфейс — по-русски, код и имена — по-английски.
7. Ноль runtime-зависимостей и сборки. Только статические файлы и ES-модули.
8. Тексты, вставленные в DOM, проходят через `escapeHtml`.

## Как вносить изменение

1. Прочитайте `docs/PRD.md` (раздел требований) и `docs/SPEC.md` (алгоритмы и контракты).
2. Если меняется правило — правьте `assets/scoring.js`, затем тест в `tests/scoring.test.mjs`.
3. Если меняется представление — правьте `assets/app.js` и `assets/styles.css`, не меняя
   публичные id и data-атрибуты без обновления спеки.
4. Запустите `npm test` и пройдите ручной чек-лист ниже.
5. Обновите документацию: PRD при изменении поведения, SPEC при изменении контракта,
   PLAN при закрытии задачи, DECISIONS при новом компромиссе.
6. Сделайте коммит в повелительном наклонении: `Добавить подсказки к шкалам`, а не
   `added hints`.

## Стиль кода

- ES-модули, `const`/`let`, без классов и прототипов.
- Отступ — 2 пробела, одинарные кавычки, точки с запятой, висячие запятые в многострочных
  литералах.
- Экспортируемые функции — с JSDoc-типами (`@param`, `@returns`).
- Никаких `innerHTML` с сырыми пользовательскими данными: только через шаблон + `escapeHtml`.
- Комментарии — по-русски и только там, где неочевиден мотив, а не пересказ кода.
- CSS — по методологии BEM-подобных классов (`.task__score`, `.focus-card__title`), токены
  в `:root`, без `!important` вне `prefers-reduced-motion`.
- Не добавляйте зависимости, CDN-шрифты и внешние картинки: приложение должно работать
  офлайн и на GitHub Pages.

## Тесты

```bash
npm test                 # node --test, 10 тестов
node --test tests/scoring.test.mjs   # точечный прогон
```

Обязательные случаи при изменении правил:

| Случай | Ожидание |
| --- | --- |
| 5/4, 3/5, 2/2 | Побеждает первая задача, 9 баллов, отрыв 1. |
| 5/2 и 2/5 | Побеждает вторая, `tieBreak === 'urgency'`. |
| 4/3 и 4/3 | Побеждает первая, `tieBreak === 'order'`. |
| Пустое имя / оценка вне 1–5 / не три задачи | `validateTasks` возвращает ошибки с полями `index`, `field`. |
| Текст объяснения | Содержит балл, отрыв или тай-брейк и профиль задачи. |

DOM-тестов в репозитории нет: интерфейс проверяется ручным чек-листом. Если добавляете
автотесты браузера, они не должны тянуть runtime-зависимости в продакшен-код.

## Ручной чек-лист перед коммитом

- [ ] `npm test` — зелёный.
- [ ] Пустая отправка: сообщение об ошибке, фокус в первом поле, шкалы подсвечены.
- [ ] Заполнение: баллы в чипах обновляются без отправки.
- [ ] Результат: карточка, объяснение, рейтинг, фокус на секции результата.
- [ ] Равные баллы: пометка «Решила срочность».
- [ ] «Изменить задачи» сохраняет значения; «Начать заново» очищает всё.
- [ ] Ширина 500 px: одна колонка, ничего не обрезается.
- [ ] Tab по форме проходит по всем полям, фокус видим.
- [ ] Консоль браузера без ошибок.

## Границы: что не добавлять

Календарь, дедлайны, статусы задач, авторизация, синхронизация, аналитика, `localStorage`,
URL-состояние, интеграции, генеративный текст, тёмная тема «на всякий случай», фреймворк
и сборщик. Всё это меняет продукт с «ритуала выбора» на трекер и требует отдельного PRD.

## Известные ловушки

- **Кириллица и PowerShell.** Не перезаписывайте файлы через `Get-Content`/`Set-Content`
  без явной кодировки UTF-8: Windows PowerShell 5.1 читает UTF-8 как ANSI и портит текст.
- **`node --test`** запускает каждый файл в дочернем процессе. В ограниченных средах это
  может падать с `EPERM`; запускайте конкретный файл напрямую.
- **`String.prototype.replaceAll`** и optional chaining требуют современного браузера;
  проект не транспилируется.
- **`:has()`** не используется как единственный механизм: выбранный сегмент дополнительно
  помечается классом `is-checked` в `syncSegmentStates`.
- **Порядок задач** — это индекс в массиве, он же `data-index`. Не сортируйте DOM: меняется
  тай-брейк по порядку ввода.
